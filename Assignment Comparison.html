  • Different scenarios and drivers (security vs infrastructure vs continuity).
  • Different Activity A risk focuses (full security register vs technical/environmental vs DRP/BCP).
  • Different Activity B emphases (control translation vs infrastructure design vs source justification).
  • Different Activity C artefacts (VLAN/WPA2 sim vs QoS-annotated sim vs backup/restore plan).
  • Different Task 2 testing emphases (permissions/GPO vs functionality/performance vs restore/DRP).
  • Different Task 3 lenses (CIA/hardening vs availability/usability/performance vs continuity/integrity + source critique).
  • Different spec points strongly evidenced (area 1 vs area 2 vs area 3).

The overlaps are limited to the shared Pearson-mandated skeleton (risk template columns, two-VLAN requirement, standard AD/DNS/DHCP build, availability as an evaluation theme) — which is exactly what you'd expect when three assignments are built on the same specification. They do not make the assignments interchangeable.

What does this mean for a student?

If a student completes all three assignments, they will have generated evidence for nearly every single point in the Occupational Specialism specification.

  • Content Area 1 (Security) is strongly driven by Assignment A, with supporting evidence from C.
  • Content Area 2 (Infrastructure) is strongly driven by Assignment B, with cable standards covered in C, and touch points in A.
  • Content Area 3 (Sources of Knowledge) is fully evidenced by Assignment C.

The only deliberate overlaps are "touch points" designed to reinforce learning. For example, all three assignments require the student to set up a basic domain (AD DS, DNS, DHCP, file shares) because that is the mandated Pearson Task 2 skeleton. However, the testing emphasis and the evaluation lens change entirely between the assignments.

9. Summary Verdict — Are there gaps in the Spec?

While the three assignments cover a strong majority of the core Performance Outcomes, there are a few specific areas that are either lightly touched upon or completely missing from these specific scenarios. If you want complete, bulletproof coverage, you should be aware of the following gaps:

Gaps / Underrepresented Areas:
  • Specific Software Applications and OS Support (PO2 gap): The spec includes "Installing, configuring and supporting software applications and operating systems". While the assignments cover Server OS and Desktop OS, they do not explicitly require the installation or configuration of a specific end-user application (e.g., installing a piece of software on the client PCs and testing it).
  • Cloud and Virtualisation Depth (PO2 gap): The spec highlights "physical and virtual infrastructure" and "cloud hosted virtual servers". The assignments mention VMs and cloud backups, but do not explicitly require designing or configuring a cloud-hosted virtual server or hybrid cloud environment.
  • Advanced Network Services (PO2 gap): The spec lists "Principles of DevOps and solution architecture". This is likely too advanced for a basic assignment and is a "touch" point rather than a core requirement.
  • Specific Legislation beyond GDPR (PO1 gap): Assignment A focuses heavily on GDPR/DPA 2018. The spec also mentions broader "Legislation and Regulatory Requirements". You could strengthen A by explicitly requiring consideration of the Computer Misuse Act 1990 or the Freedom of Information Act.
Final Verdict:

Is it a good portion of the spec? Yes, absolutely. It covers the three Performance Outcomes comprehensively.

Is it 100% complete? No. The main gaps are specific application software support and cloud/virtualisation design.

How to fix it: You don't need a whole new assignment. Add one small sub-task to Assignment B (Infrastructure) that asks the student to:

  1. Install and test a specific application on the client PCs.
  2. Propose a cloud-hosted solution for a secondary service (e.g., a web server) and justify why it is cloud-based rather than on-premises.
