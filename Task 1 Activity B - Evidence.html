Assignment B — Meridian Logistics (Infrastructure-framed)

Task 1 Activity B — Infrastructure Requirements 18 marks
Scenario: Logistics firm consolidating two offices, 20 users, operations & finance departments, shared building, VLAN separation, WPA2 Wi-Fi.
Requirement: Lean into content area 2 — network topology (star/client-server), IP addressing and subnetting (two VLANs), device selection, server roles, remote access method comparison (RDP vs VPN vs SSH), and backup criteria.
Top-band model answer (Band 4 — 15–18 marks): The requirements document below covers topology, subnetting, device selection, server roles, remote access comparison and backup criteria, with every decision justified.

1. Network topology

Selected topology: Star / client-server

  • Star topology at the physical layer: all devices connect to a central managed switch.
  • Client-server model at the logical layer: a central server provides AD DS, DNS, DHCP and file services.

Justification:

  • Star topology is easy to troubleshoot (one device failure does not take down the network — mitigates Risk 1, single point of failure at the edge).
  • Centralised management of users, permissions and policies (mitigates Risk 4, misconfiguration).
  • Scalable — additional switches and WAPs can be added without redesign.
  • Client-server supports centralised backup and security policy enforcement.

Alternatives considered: Mesh (overkill for 20 users, costly); peer-to-peer (no central management, unsuitable for 20 users with shared folders).

Subnetting rationale: /24 provides 254 usable hosts per VLAN — sufficient for 10 users per department plus growth, printers and management interfaces. /24 is simple to document and troubleshoot. If growth to 50+ users per department is expected, a /23 could be used (510 hosts), but /24 is appropriate for the stated 20-user requirement.

Routing: Inter-VLAN routing via Layer 3 switch. DHCP relay (ip helper-address) on each VLAN interface pointing to the DHCP server.

5. Remote access method — comparison and justification

MethodSecurityUse caseComplexityJustification for selection
RDP Medium — encrypted, but exposed to brute force if internet-facing LAN-only remote desktop to the server Low Selected for LAN administration only. RDP is convenient for on-site admin, but not safe to expose directly to the internet. Combined with VPN for remote use.
VPN High — encrypted tunnel, strong authentication Remote access for staff and administrators Medium Selected for remote access. VPN provides a secure encrypted tunnel for remote administration and remote workers. Mitigates Risk 2 (network dropout) by allowing secure remote work.
SSH High — encrypted Linux server administration Low–medium Not applicable — the server runs Windows Server, so SSH is not the primary admin protocol. Could be used for network device management.

5. TIA/EIA-568 cable standard — justification with sources

Decision: Use Cat 6 UTP cable wired to TIA/EIA-568-B pinout, tested to TIA/EIA-568.

SourceTypeReliability / validityBias flag
TIA/EIA-568 (Telecommunications Industry Association / Electronic Industries Alliance) Industry standard Authority: high (standards body). Date: current revision. Version: 568-B. Corroboration: widely adopted. Low — neutral standards body.
NCSC guidance on network cabling Government guidance Authority: high (UK government). Date: current. Corroboration: aligns with TIA/EIA-568. Low — neutral government body.
Vendor whitepaper (e.g. cable manufacturer) Vendor documentation Authority: medium (vendor has commercial interest). Date: current. Corroboration: cross-checked against TIA/EIA-568. High — vendor bias; used only to corroborate, not as sole source.

Justification: TIA/EIA-568 is the recognised industry standard for structured cabling; Cat 6 supports 1 Gbps up to 100 m and 10 Gbps up to 55 m, sufficient for the office. Using TIA/EIA-568-B pinout ensures compatibility with standard patch panels and outlets. Testing to TIA/EIA-568 confirms the cable meets performance requirements.

6. Backup type — justification with sources

Decision: Hourly incremental + weekly full backup, with off-site cloud copy.

SourceTypeReliability / validityBias flag
NCSC guidance on backup and recovery Government guidance Authority: high. Date: current. Corroboration: aligns with industry best practice. Low — neutral government body.
Microsoft documentation on Windows Server Backup Vendor documentation Authority: high for product-specific steps. Date: current. Corroboration: cross-checked with NCSC. Medium — vendor bias toward its own product; used for product-specific configuration only.

Weekly full backup provides a clean restore point. Off-site cloud copy mitigates the risk of local backup media being destroyed or stolen (Risk 3, Risk 5, Risk 8). The choice is corroborated by NCSC guidance and ITIL/ISO 22301 continuity best practice.
