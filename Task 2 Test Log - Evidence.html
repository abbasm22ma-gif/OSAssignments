Unified Mark Scheme — Task 2 Test Log (30 marks)

This single-page mark scheme displays the generic banding criteria alongside the specific, contextualised testing requirements for Assignments A, B, and C. The exemplar logs in the other tabs are designed to meet the Band 4 criteria across all columns, demonstrating iterative troubleshooting (failures, corrective actions, and successful retests).

Band Marks Generic Assessment Criteria (All Assignments) Assignment A (Security) Assignment B (Infrastructure) Assignment C (Continuity)
4 25–30 Comprehensive test log demonstrating iterative testing. Includes initial failures, accurate diagnosis of root causes, corrective actions applied, and successful retests. Evidence is fully annotated with screenshots. All required test criteria for the specific assignment are met. Focuses on permission testing and GPO testing. Proves RBAC matrix, lockout policies, and security GPOs are enforced. Focuses on functionality and performance. Proves VLAN routing, DHCP/DNS, service reachability (IIS), and VPN remote access. Focuses on backup/restore (centrepiece), DRP tabletop, and cable testing. Proves data integrity, RTO/RPO, and TIA/EIA-568 standard.
3 19–24 Detailed test log. Most tests show expected outcomes and actual outcomes. Some corrective actions are noted, but evidence of retesting may be limited or inconsistent. Annotated screenshots are present but may lack depth. Covers most security tests but misses retests for some failures, or lacks annotated evidence for GPO enforcement. Covers most infrastructure tests but misses retests for some failures, or lacks performance metrics. Covers backup tests but misses the DRP tabletop or cable testing, or lacks retest evidence.
2 11–18 Adequate test log. Basic tests are recorded, but there is limited evidence of troubleshooting, corrective actions, or retesting. Screenshots may be missing or lack annotation. Basic security tests recorded, but no evidence of negative testing or GPO verification. Basic infrastructure tests recorded, but no evidence of troubleshooting or performance checks. Basic backup tests recorded, but no evidence of restore proof or DRP validation.
1 1–10 Limited test log. Few tests recorded. Little or no evidence of corrective actions or retesting. Screenshots missing or irrelevant. Minimal security testing. Minimal infrastructure testing. Minimal continuity testing.
0 0 No creditable response.
How the exemplars achieve Band 4 (Distinction):
  • Iterative Testing: Each log includes at least one intentional failure, a clear diagnosis of the root cause (e.g., unlinked GPO, wrong VLAN, FAT32 limit), a corrective action, and a successful retest.
  • Contextual Testing: The tests are not generic; they prove the specific controls and infrastructure required by the scenario.
  • Evidence: The log references annotated screenshots for every step, ensuring the process is fully auditable.
Assignment A (Northgate Health Trust) — Testing Emphasis: Permission testing and GPO testing — proving the security controls work. Note: Includes an initial failure due to a missing GPO link, demonstrating iterative troubleshooting.
Description of test Expected outcome Actual outcome Comments and corrective actions
1. Domain Login & Password Policy
Attempt to log in as Clinical_User. Attempt to set a password shorter than 12 characters.		 User logs in. The system rejects the short password and displays an error. Pass
Login successful. Password change rejected with error: "Password does not meet the length requirements of the domain."		 Password policy GPO applied correctly at the domain root. No corrective action needed. (Evidence: Screenshot 1)
2. Security GPO — USB Restriction
Log in as Clinical_User. Insert a USB flash drive and attempt to copy a file to it.		 The USB drive is detected, but the system denies write access. Fail
The file copied to the USB drive successfully without any restriction.		 Corrective Action: Checked Group Policy Management. The GPO was created but not linked to the Clinical Admin OU. Linked the GPO and ran gpupdate /force.
2a. Retest — USB Restriction
Log out and back in as Clinical_User. Attempt to copy a file to the USB drive again.		 The system denies write access to the removable drive. Pass
File copy failed. Error message: "You do not have permission to save in this location."		 Removable Storage Access GPO now applied and enforced correctly. (Evidence: Screenshot 2 & 3)
3. Shared Folder Permissions (RBAC)
Log in as Finance_User. Attempt to open \\Server\Clinical.		 Access Denied for Clinical folder due to RBAC matrix restrictions. Fail
Access was granted. The user could see and open files in the Clinical share.		 Corrective Action: Found that the Domain Users group was accidentally left in the NTFS permissions with Read access. Removed Domain Users and ensured only the Clinical_Group and Domain Admins had access.
3a. Retest — Folder Permissions
Log in as Finance_User. Attempt to open \\Server\Clinical and \\Server\Finance.		 Access Denied for Clinical. Access Granted for Finance. Pass
Access denied to Clinical share. Successfully modified a file in the Finance share.		 Cross-departmental isolation verified. NTFS permissions corrected. (Evidence: Screenshot 4)
4. Account Lockout Policy
Attempt to log in as Finance_User with an incorrect password 5 times.		 After the 5th attempt, the account locks out for 30 minutes. Pass
Account locked after 5 failures. A 6th attempt with the correct password was rejected.		 Account Lockout GPO applied correctly. No corrective action needed. (Evidence: Screenshot 5)
Assignment B (Meridian Logistics) — Testing Emphasis: Functionality and performance — proving service reachability and network routing. Note: Includes a failed ping test due to VLAN misconfiguration, demonstrating network troubleshooting.
Description of test Expected outcome Actual outcome Comments and corrective actions
1. DHCP Lease & Network Connectivity
On Operations workstation, run ipconfig /all and ping 192.168.10.1.		 Workstation has a 192.168.10.x IP. Ping to the gateway succeeds. Pass
IP 192.168.10.100 obtained. Ping successful (Average 1ms).		 DHCP scope functioning. Basic connectivity established. (Evidence: Screenshot 1)
2. VLAN Isolation & Inter-VLAN Routing
From Operations PC, ping the Finance PC (192.168.20.100) and ping the Server (192.168.40.10).		 Ping to Finance fails (blocked by ACL). Ping to Server succeeds. Fail
Ping to Finance PC succeeded. Ping to Server failed (Request Timed Out).		 Corrective Action: Checked the L3 switch configuration. The switchport for the Finance PC was incorrectly assigned to VLAN 10, not VLAN 20. The ACL was also applied to the wrong interface. Corrected VLAN assignments and re-applied ACL to VLAN 20 inbound.
2a. Retest — VLAN Routing & ACLs
From Operations PC, run ping 192.168.20.100 and ping 192.168.40.10.		 Ping to Finance fails (Request Timed Out). Ping to Server succeeds. Pass
Finance PC ping failed (100% loss). Server ping succeeded (0% loss).		 Inter-VLAN routing and ACLs are functioning as designed. (Evidence: Screenshot 2)
3. DNS Resolution (External)
On Operations workstation, run nslookup www.bbc.co.uk.		 The DNS server resolves the external domain using forwarders. Pass
Non-authoritative answer returned with multiple public IPs.		 DNS Forwarders configured correctly. (Evidence: Screenshot 3)
4. Service Reachability (IIS)
Open a browser and navigate to http://intranet.meridian.local.		 The IIS default page loads successfully. Fail
Browser displayed "This site can't be reached - DNS_PROBE_FINISHED_NXDOMAIN".		 Corrective Action: The IIS service was installed, but no DNS A record was created for intranet. Opened DNS Manager and created a new A record pointing to the web server's IP.
4a. Retest — Service Reachability
Refresh the browser at http://intranet.meridian.local.		 The internal intranet site loads successfully. Pass
Intranet site loaded showing "Welcome to Meridian Logistics".		 Application service deployed and DNS record correctly mapped. (Evidence: Screenshot 4)
5. Remote Access — VPN
From external host, connect via VPN and RDP to server.		 VPN establishes. RDP over VPN connects to the server. Pass
VPN connected, and RDP succeeded over the internal IP (192.168.40.10).		 VPN provides secure remote access; RDP exposed only internally. (Evidence: Screenshot 5)
Assignment C (Harbourview Media) — Testing Emphasis: Restore-from-backup proof and DRP tabletop walkthrough. Note: Includes a failed backup test due to the external drive being formatted as FAT32 (size limit), demonstrating capacity/format troubleshooting.
Description of test Expected outcome Actual outcome Comments and corrective actions
1. Backup Verification — Initial Run
Create a 10GB test video file in the Production share. Run the scheduled backup to the external drive.		 The backup completes successfully and the file is stored on the external drive. Fail
Backup job failed with error: "The file is too large for the destination file system."		 Corrective Action: The external drive was pre-formatted as FAT32 (which has a 4GB file size limit). Reformatted the drive as NTFS and encrypted it with BitLocker.
1a. Retest — Backup Verification
Re-run the backup job to the newly formatted NTFS drive.		 The backup completes successfully. Pass
Backup completed with 0 errors. Windows Server Backup console shows the 10GB file was included.		 Backup functioning. RPO maintained. (Evidence: Screenshot 1)
2. Restore Test — File Level (Centrepiece)
Delete the 10GB video file. Open Windows Server Backup and restore it.		 The file is restored to its original location. Pass
File restored successfully in 3 minutes. Video plays correctly.		 Proof that the backup is usable and meets the RTO. (Evidence: Screenshot 2)
3. Backup Offline/Encryption Check
Verify the external drive is BitLocker encrypted. Attempt to open it on a standalone PC.		 The drive prompts for the 48-digit recovery key on the standalone PC. Pass
BitLocker active. Standalone PC prompted for recovery key.		 Mitigates Risk 8 (backup theft). (Evidence: Screenshot 3)
4. DRP Tabletop Walkthrough
Simulate a disk failure on the server (disconnect virtual disk). Follow the DRP runbook to recover the service.		 Steps followed: 1. Identify failure. 2. Provision new storage. 3. Restore from off-site backup. 4. Verify data integrity. Pass
Walkthrough completed in 45 minutes. Runbook steps were clear.		 Identified that the cloud download step needs a faster connection. Corrective action: Recommend upgrading the backup internet link to reduce MTTR. (Evidence: DRP_Walkthrough_Log.pdf)
5. Cable Test — TIA/EIA-568
Use a cable tester on a newly made Cat 6 patch cable.		 Tester shows 1-to-1 continuity for all 8 pins. Fail
Tester showed lights 1, 2, 3, and 6 only. Pins 4, 5, 7, and 8 were dead.		 Corrective Action: Inspected the RJ45 connector. The wires for pins 4, 5, 7, 8 were not pushed fully into the connector before crimping. Cut the end off and re-crimped with a new RJ45 plug, ensuring all wires pushed to the end.
5a. Retest — Cable Test
Use the cable tester on the re-crimped patch cable.		 Tester shows 1-to-1 continuity for all 8 pins. Pass
Cable tester lights illuminated sequentially 1 through 8 on both ends.		 Standard compliance verified. (Evidence: Photo_Cable_Test.jpg)
